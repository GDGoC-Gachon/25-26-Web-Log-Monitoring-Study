## 요구사항

| ID | 요구사항 | 상태 |
|----|----------|------|
| REQ-MAIL-001 | 한 폴링에서 탐지 결과가 존재하면 SMTP를 통해 설정된 수신자에게 알림 발송을 시도해야 한다. | 구현됨 |
| REQ-MAIL-002 | 현재 정적 단계의 SMTP 접속 정보와 운영자·도메인별 수신자 목록은 환경 변수로 관리해야 한다. | 구현됨 |
| REQ-MAIL-003 | 탐지 결과가 없으면 메일을 발송하지 않아야 한다. | 구현됨 |
| REQ-MAIL-004 | 현재 단계의 도메인별 수신자는 `SMTP_DOMAIN_RECIPIENTS` 정적 매핑을 기준으로 결정해야 한다. Elastic 계정 연동은 별도 요구사항으로 관리한다. | 구현됨 |
| REQ-MAIL-005 | 운영자 수신자는 모든 도메인의 탐지를 수신해야 한다. | 구현됨 |
| REQ-MAIL-006 | 서비스 사용자는 등록한 `hostDomain`의 탐지만 제목과 본문에서 확인할 수 있어야 한다. | 부분 구현 |
| REQ-MAIL-007 | SMTP 실패 시 비밀번호와 인증값 없이 오류를 기록하고 탐지 프로세스가 종료되지 않아야 한다. | QA 필요 |
| REQ-MAIL-008 | 수신자별 권한으로 알림 목록을 먼저 필터링한 뒤 별도 본문을 생성해야 한다. | 계획 |
| REQ-MAIL-009 | 제목과 본문에 탐지 유형, 시간 창, 대상, IP, 경로, 임계값, 실제 값, 권장 조치를 읽기 쉬운 구조로 표시해야 한다. | 계획 |
| REQ-MAIL-010 | DDoS 알림은 전체 요청 수와 `hostDomain`별 요청 수를 표시해야 한다. | 계획 |
| REQ-MAIL-011 | 폴링·사건 ID와 수신자별 발송 성공·실패를 감사 가능하게 추적해야 한다. | 계획 |
| REQ-MAIL-012 | 메일은 HTML 본문과 같은 핵심 정보를 담은 plain-text 대체 본문을 함께 제공해야 한다. | 계획 |
| REQ-MAIL-013 | 도메인, 경로, IP, 오류 사유 등 HTML에 삽입하는 동적 값을 이스케이프해 태그·스크립트로 해석되지 않게 해야 한다. | 계획 |

## 확인된 구현 차이

현재 구현은 알림 중 하나와 도메인이 일치하면 서비스 사용자를 수신자로 선정한 뒤, 선정된 모든 수신자에게 해당 폴링의 전체 알림 배열을 같은 본문으로 보낸다. A와 B 도메인 알림이 같은 폴링에 있으면 A 사용자가 B의 정보까지 받을 수 있으므로 `REQ-MAIL-006`을 충족하지 않는다. 실제 배포 환경에서 [회귀 QA](../test-plans/2026-07-06-detection-regression.md)로 재현한다.

현재 SMTP 데이터는 `Content-Type: text/plain; charset=utf-8`로만 만들어진다. PDF에서 제안한 Resend 템플릿은 대안 중 하나이며, Resend 채택 자체를 확정 요구사항으로 보지 않는다. 기존 SMTP에서 `multipart/alternative`를 직접 구성하는 방안과 운영·보안·테스트 비용을 비교한 뒤 결정한다.

## 수용 기준

| ID | 시나리오 | 기대 결과 |
|----|----------|-----------|
| AC-MAIL-001 | 알림 없음 | SMTP 연결과 메일 발송 없음 |
| AC-MAIL-002 | A와 B 알림 동시 발생 | A 사용자 본문에는 A만, B 사용자 본문에는 B만 포함 |
| AC-MAIL-003 | 같은 상황에서 운영자 수신 | 한 메일 또는 승인된 형식으로 A와 B 전체 확인 |
| AC-MAIL-004 | 여러 도메인 DDoS | 운영자 본문에 도메인별 요청 수 표시 |
| AC-MAIL-005 | SMTP 인증 또는 네트워크 실패 | 실패가 기록되고 자격 증명은 기록되지 않음 |
| AC-MAIL-006 | HTML을 표시하는 메일 클라이언트 | 탐지별 유형·대상·심각도·근거·권장 조치를 시각적으로 구분 |
| AC-MAIL-007 | HTML을 표시하지 않는 메일 클라이언트 | plain-text 본문에서 같은 핵심 정보 확인 |
| AC-MAIL-008 | 경로나 오류 사유에 `<`, `>`, `&`, 따옴표가 포함됨 | 텍스트로 표시되고 HTML 구조나 링크를 주입하지 않음 |

## 발송 시점

“즉시 알림”은 탐지 결과가 만들어진 뒤 지체 없이 발송을 시도한다는 의미다. 로그 발생 시점 기준으로는 다음 정상 폴링과 Elastic 조회가 끝난 뒤 발송되므로, 실제 도착 지연은 폴링 주기와 외부 시스템 처리 시간을 포함해 QA에서 측정한다.
