# 탐지·알림 회귀 QA 계획

| 항목 | 내용 |
|------|------|
| 상태 | 오류율 하한 자동 테스트 통과 · 실서버 QA 실행 전 |
| 우선순위 | P0 |
| 출처 | [2026-07-06 시연 후 재QA](../meeting-notes/2026-07-06-monitoring-system.md), [2026-07-11 오류·기능개선 사항](../feedback/2026-07-11-error-and-feature-improvements.md) |
| 대상 | 탐지 5종, 오류율 트래픽 하한선, 메일 라우팅·표현, Elastic 사용자 연동, 폴링 수명주기, 부분 장애 |
| 마지막 갱신 | 2026-07-13 |

이 문서는 자동 테스트와 실제 환경 QA의 실행 계획·증적 형식을 정의한다. 오류율 트래픽 하한선 자동 테스트는 통과했지만 아래 실서버·SMTP 시나리오는 수행 전까지 통과로 표시하지 않는다.

회의가 직접 요청한 범위는 탐지 재QA, 다중 도메인 오동작, 중복·혼재 알림, 시연 재현이다. 추가 PDF가 직접 요청한 범위는 저표본 오류율 오탐 방지, 메일 가독성, Elastic role 기반 수신 범위다. 폴링 중복, Job 실패, 5xx 대상 범위, HTML 이스케이프, 비활성 사용자 제외는 현재 코드·응답 필드를 근거로 추가한 회귀 제안이다.

## 사전 조건

- 테스트용 도메인 A·B와 각 도메인 전용 수신자, 전체 수신 운영자를 준비한다.
- 실제 계정·비밀번호·메일 주소는 문서와 로그에서 마스킹한다.
- 실행 전 비밀값을 제외한 폴링 주기, 조회 창, 각 탐지 임계값, 예외 목록을 기록한다.
- 4xx·5xx 최소 요청 수의 제품 기본값은 각각 20이다. 테스트에서 값을 재정의하면 실행 증적에 명시한다.
- 원시 요청 ID 또는 발생 시각, Elastic 조회 결과, 애플리케이션 로그, 수신 메일을 연결할 수 있게 한다.
- 운영 방화벽이나 실제 사용자 데이터에 영향을 주는 요청은 사용하지 않는다.

## 메일 검증 항목

- [ ] 제목에서 탐지 유형과 대상 범위를 식별할 수 있다.
- [ ] 본문에 발생 시간 창, `hostDomain`, `clientIp`, 경로, 임계값, 실제 값이 필요한 만큼 표시된다.
- [ ] 도메인 사용자의 제목·본문·헤더에 타 도메인 정보가 없다.
- [ ] DDoS에서 도메인별 요청 수가 표시된다.
- [ ] 동일 사건의 중복 발송 여부를 확인할 수 있다.
- [ ] 실패 시 비밀번호와 SMTP 인증값 없이 원인을 추적할 수 있다.
- [ ] HTML 지원 클라이언트에서 탐지별 정보 계층과 권장 조치를 구분할 수 있다.
- [ ] plain-text 대체 본문에 HTML과 같은 핵심 정보가 있다.
- [ ] 도메인·경로·오류 사유의 특수문자가 HTML 구조나 링크를 주입하지 않는다.
- [ ] Resend를 검토한다면 UI 미리보기만이 아니라 실제 수신 메일을 데스크톱·모바일에서 확인한다.

## 증적 형식

각 실행 결과에 다음 정보를 남긴다.

| 필드 | 내용 |
|------|------|
| 실행 ID | 재실행과 구분 가능한 값 |
| commit | 테스트한 Git commit |
| 환경 | 로컬/스테이징, 비밀값 제외 설정 |
| 입력 | 요청 수, IP·도메인 마스킹값, 시간 범위 |
| 관찰 | 탐지 로그, 사건 수, 메일 수신자·도착 시간 |
| 결과 | 통과/실패/차단됨 |
| 이슈 | 재현 절차와 관련 요구사항 ID |

## 완료 기준

- P0 시나리오가 모두 통과하거나, 실패 항목마다 재현 가능한 이슈와 담당자가 정해진다.
- 회의 시연과 현재 `main` 출력이 다른 항목은 배포 commit과 설정 차이를 확인한다.
- 결과를 [요구사항 대시보드](../requirements-definition.md) 상태와 [후속 개발 계획](../PLANS.md)에 반영한다.
